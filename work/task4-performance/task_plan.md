# Task Plan: 单体与微服务性能对比

## Goal
在同一台机器、同一受控数据集、同一压力脚本和相同参数下，对 2–3 个主要接口分别运行单体版和微服务版至少 3 次，保留请求与 CPU/内存原始结果，诚实解释差异。

## Phases
- [x] Phase 1: 审计启动方式、数据模型、接口与资源条件
- [x] Phase 2: 固化公平实验设计和失败契约
- [x] Phase 3: 实现隔离环境、固定数据、统一压测与采样脚本
- [x] Phase 4: 执行单体版至少 3 轮
- [x] Phase 5: 执行微服务版至少 3 轮
- [x] Phase 6: 聚合、复核、报告与全量回归

## Non-negotiable controls
- 同一宿主机，同一时段；两套应用顺序运行，避免互相争抢资源。
- 同一份逻辑数据和同一 PostgreSQL 服务器；不使用用户现有业务数据做不可逆修改。
- 同一压力程序、接口语义、并发、持续时间、超时和预热策略。
- 每个接口每个版本至少 3 个独立原始结果；报告中保留全部轮次。
- CPU/内存按参与请求的应用容器求和，同时保留逐容器采样。
- 不以架构推断性能；只描述测得结果和适用边界。

## Status
**Complete** - 三轮主对比、过载对照、原始证据、正式报告和全量回归均完成。

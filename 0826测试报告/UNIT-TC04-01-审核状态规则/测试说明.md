# UNIT-TC04-01 审核状态规则单元测试说明

## 做什么测试

测试 `StreamHub/backend/app/schemas.py` 中的 `AuditIn` 输入模型。该模型是管理员审核视频接口的输入边界。

业务规则：管理员只能将视频审核为“通过”(`1`)或“驳回”(`2`)；“待审核”(`0`)和其他任意整数不能作为审核决定写入数据库。

## 测试过程

1. 新建 `StreamHub/backend/tests/test_audit_rules_unit.py`。
2. 先运行测试，不修改生产代码。`AuditIn(auditStatus=0)` 未抛出 `ValidationError`，测试按预期失败。
3. 将 `AuditIn.auditStatus` 从 `int` 改为 `Literal[1, 2]`。
4. 重新运行同一测试，确认合法值通过、非法值抛出 `literal_error`。
5. 单进程运行完整后端回归，确认新规则没有破坏既有后端测试。

## 测试内容与断言

| 输入 | 预期 | 断言 |
|---|---|---|
| `auditStatus=1` | 通过 | 返回值等于 `1` |
| `auditStatus=2` | 通过 | 返回值等于 `2` |
| `auditStatus=0` | 拒绝 | 抛出 `ValidationError`，错误类型为 `literal_error` |
| `auditStatus=3` | 拒绝 | 同上 |
| `auditStatus=-1` | 拒绝 | 同上 |

测试直接实例化 Pydantic 模型，使用 `--noconftest`，不启动 FastAPI、不访问数据库；因此这是单元测试，不是 API 测试。

## 测试结果

- RED：1 failed。旧实现接受 `0`，证明测试能检出缺陷。
- GREEN：1 passed，耗时 0.34 秒。
- 后端回归：15 passed，0 failed，0 error，58 warnings，耗时 52.28 秒。

# 给小白看的：单元测试在测什么？

## 一句话

这份测试是在检查：**管理员审核视频时，系统会不会只接受“通过”或“驳回”，不会接受乱填的审核结果。**

它不是在测试整套网页，也不是在测试管理员是否能登录。它只检查最小的一条业务规则。

## 为什么要测？

视频审核只有两种最终结果：

- 通过
- 驳回

如果系统把“审核中”、`3`、`-1` 之类乱七八糟的状态也当成合法结果，视频可能会被错误改回待审核，数据就会混乱。

所以先用单元测试守住这个最基础的规则。它像检查一颗螺丝是否合格：快、定位准、出错时知道是规则错了。

## 怎么测？

测试分别把不同审核结果交给系统：

| 输入 | 期望结果 |
|---|---|
| 通过 | 系统接受 |
| 驳回 | 系统接受 |
| 审核中 / 0 | 系统拒绝 |
| 3、-1 等非法数字 | 系统拒绝 |

测试有明确判断，不是只看程序有没有崩：合法输入必须成功，非法输入必须出现校验错误。

## 结果是什么？

- 这个单元测试：**1 个测试，1 个通过，0 失败。**
- 后续完整后端回归：**18 个测试，18 个通过。**

以前系统确实会接受非法状态 `0`。测试先把这个问题测出来，之后把规则限制为“只能通过或驳回”，再重跑测试才通过。

## 它没有测什么？

它**没有**证明管理员页面能不能点“通过”，也没有证明数据库有没有保存成功。

这些事情由下一层的 API/集成测试来测；用户从网页完成整套流程，则由端到端测试来测。

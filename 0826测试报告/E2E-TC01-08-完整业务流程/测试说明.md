# E2E-TC01-08 端到端测试说明

## 做什么测试

从浏览器页面入口完成已确认业务场景 UC01–UC08 的完整流程。三个用例使用真实前端、FastAPI、PostgreSQL、浏览器和直播 WebSocket；不是只调用函数，也不是只看是否报错。

**范围事实：**业务清单中 UC01–UC08 标为已实现、建议计入；UC09–UC19 为未实现、静态模拟或待教师确认。本报告只声称覆盖 UC01–UC08，不能声称“全部 19 个业务场景已覆盖”。

| 用例 | 覆盖的业务场景 | 关键断言 |
|---|---|---|
| E2E-TC01-02 | UC01 搜索并播放视频；UC02 评论、视频弹幕 | 路由进入搜索/视频页；`video` 可见；评论、弹幕 POST 响应成功；评论显示；弹幕输入清空 |
| E2E-TC03-05 | UC03 创作者投稿；UC04 管理员审核；UC05 创作者查看结果 | 投稿成功提示；投稿在创作者中心为“审核中”；管理员通过；创作者中心显示“已通过” |
| E2E-TC06-08 | UC06 创建直播；UC07 观众连接并发送直播弹幕；UC08 结束直播 | 创建后路由进入直播间；聊天连接；消息显示；结束接口成功；刷新后页面显示“已结束” |

## 测试过程

1. Playwright 启动当前 `StreamHub` 源码的后端 `127.0.0.1:8001` 与前端 `127.0.0.1:3267`；不复用本机 `8000/3266` 的另一份服务。
2. 前端构建时注入 E2E 后端地址；后端仅允许本次前端来源，并用 UTF-8 启动，避免 Windows 控制台中文输出导致启动失败。
3. Playwright 串行执行三个完整流程；JUnit、失败截图、视频、Trace 写入本目录 `证据`。
4. 先故意把 E2E 后端指向旧 `8000`：用例失败，门禁返回非零，发布和部署标记为跳过。随后恢复隔离后端。
5. 发现初版直播结束请求写死 `8000`、并发现 WebSocket 断线竞态；先写回归测试复现，再修复，最后完整套件连续运行两次。

## 测试内容与结果

### E2E-TC01-02：搜索、播放、评论和弹幕

- **内容：**普通用户登录，搜索“视频”，进入首个视频，发表评论并发送视频弹幕。
- **过程：**页面输入、跳转和媒体元素可见；监听 `POST /comments`、`POST /danmaku` 并断言响应 `ok`；检查评论文本和输入框状态。
- **结果：**最终第 1、2 轮均通过。
- **证据：**`证据/e2e-post-fix-full-run-1.xml`、`证据/e2e-post-fix-full-run-2.xml`；两份报告均记录该用例 `failures=0`。

### E2E-TC03-05：投稿、审核、查看审核结果

- **内容：**创作者发布演示视频，管理员审批，创作者重新登录查看状态。
- **过程：**页面依次断言“投稿成功，等待管理员审核”“审核中”“视频已通过审核。”“已通过”。
- **结果：**最终第 1、2 轮均通过。
- **证据：**`证据/e2e-post-fix-full-run-1.xml`、`证据/e2e-post-fix-full-run-2.xml`。

### E2E-TC06-08：创建直播、直播聊天、结束直播

- **内容：**创作者从页面创建直播；观众从页面进入、连接聊天并发弹幕；创作者通过当前 E2E 后端接口结束直播，观众刷新页面确认结束。
- **过程：**断言直播 URL、聊天室“聊天已连接”、弹幕文本、结束接口成功和“已结束”页面状态。结束动作使用接口入口，符合“页面或接口入口”的课程表述；它不是纯 UI 点击结束按钮。
- **结果：**最终第 1、2 轮均通过；修复后端日志未出现此前的 WebSocket ASGI 未处理异常。
- **证据：**`证据/e2e-post-fix-full-run-1.xml`、`证据/e2e-post-fix-full-run-2.xml`、`证据/pipeline-post-fix-full-run-1.log`、`证据/pipeline-post-fix-full-run-2.log`。

# 给小白看的：API / 集成测试在测什么？

## 一句话

这份测试是在检查：**不同身份的人通过后端接口操作视频审核时，系统会不会正确登录、正确拦权限、正确写进数据库。**

它比单元测试大一层：不只检查“规则对不对”，还检查接口、身份、数据库能不能一起工作。

## 为什么要测？

单元测试说“只有通过或驳回是合法状态”，但还可能出现这些问题：

- 普通用户居然能审核视频。
- 管理员审核了，但数据库没有真的保存。
- 请求了不存在的视频，系统不是返回清楚的错误，而是直接崩掉。
- 非法状态被接口接受，偷偷改坏数据。

所以 API/集成测试要把“登录身份 → 调接口 → 数据库结果”连起来检查。

## 怎么测？

测试会用三个演示账号登录：普通用户、创作者、管理员。然后调用真实后端接口，并查看真实测试数据库。

| 场景 | 期望结果 |
|---|---|
| 创作者投稿，管理员审核通过 | 成功，数据库状态变为“已通过” |
| 管理员驳回投稿 | 成功，数据库状态变为“已驳回” |
| 普通用户尝试审核 | 被拒绝，不能越权 |
| 管理员把视频改回“审核中” | 被拒绝，数据库状态不变 |
| 管理员审核不存在的视频 | 返回“视频不存在”错误 |
| 直播创建、结束、聊天消息 | 权限、接口、WebSocket 消息正确 |

这类测试还会先登录，确认身份令牌能正常使用；重点不是“登录页面长什么样”，而是接口能否识别正确身份。

## 结果是什么？

- 审核 API/数据库测试：**6 个测试，6 个通过，0 失败。**
- 后续完整后端回归：**18 个测试，18 个通过。**

还故意做过一次失败验证：临时让系统接受非法审核状态 `0`。测试马上失败，门禁退出，发布和部署被标记为跳过。之后已恢复正确规则。

## 它没有测什么？

它不重点检查用户是否能在浏览器页面找到按钮、页面会不会跳转、提示文字有没有出现。

这些属于端到端测试。API 测试证明“后端能正常做事”；端到端测试证明“用户能正常完成事情”。

## 数据安全吗？

这类测试使用 `streamhub_test` 测试数据库。每个测试前后会重建测试表，不会拿演示库当测试库。

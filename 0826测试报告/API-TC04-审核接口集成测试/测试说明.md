# API-TC04 审核接口集成测试说明

## 做什么测试

测试管理员审核视频接口 `PATCH /api/admin/videos/{video_id}/audit`。测试经过 HTTP API、登录鉴权、Pydantic 请求校验、FastAPI 路由、SQLAlchemy 和 PostgreSQL 测试库。

本组覆盖审核用例主成功流程、备选流程和异常流程。`TestClient` 调用 API 合约，数据库使用真实 `streamhub_test`；它不是部署后的 Docker 网络测试，也不是端到端页面测试。

## 代码地址

- 现有 API 测试组：`SE2026-main\backend\tests\test_video_flow_api.py`
- 本次新增测试：同文件第 137 行 `test_admin_cannot_return_submitted_video_to_pending`；第 167 行 `test_admin_cannot_audit_nonexistent_video`。
- API 路由：`SE2026-main\backend\app\main.py:849`
- 请求校验依赖：`SE2026-main\backend\app\schemas.py:115-116`。
- 测试 DB fixture：`SE2026-main\backend\tests\conftest.py:16-28`。
- 新增门禁代码：`SE2026-main\0826测试报告\API-TC04-审核接口集成测试\run-api-tc04-gate.ps1`。

本次没有新增或修改第二类测试的生产代码。`AuditIn.auditStatus = Literal[1, 2]` 是第一类单元测试已完成的输入校验，本组验证该规则是否真正阻止 API 写入数据库。

## 测试过程

1. 运行既有 `test_video_flow_api.py`，基线为 4 passed。
2. 在同一测试文件追加两条缺失异常用例。
3. 运行完整 API 文件，得到 6 passed。
4. 受控回归：临时把 `AuditIn.auditStatus` 改回 `int`，运行新增非法状态 API 测试。接口返回 `200`，断言预期 `422` 失败；门禁停止后续发布、部署。
5. 立即恢复 `Literal[1, 2]`，运行门禁、6 条 API 测试和完整后端回归。

受控回归只使用 `streamhub_test`；测试 fixture 每例删建表。没有访问 `streamhub` 演示库。

## 测试内容

| 用例 | 流程类型 | 覆盖内容 | 关键断言 |
|---|---|---|---|
| `test_creator_submit_then_admin_approve_video` | 主成功 | 创作者投稿、管理员待审列表、通过、创作者查询 | `200`；待审状态 `0`；审核后状态 `1` |
| `test_admin_can_reject_submitted_video` | 备选 | 管理员驳回投稿 | `200`；状态 `2` |
| `test_normal_user_cannot_audit_video` | 异常/权限 | 普通用户调用审核接口 | `403` |
| `test_admin_cannot_return_submitted_video_to_pending` | 异常/校验 | 管理员提交 `auditStatus=0` | `422`；`literal_error`；查询 DB 后仍为 `0` |
| `test_admin_cannot_audit_nonexistent_video` | 异常/资源 | 管理员审核不存在 UUID | `404`；`视频不存在` |
| `test_normal_user_cannot_submit_video` | 关联权限 | 普通用户调用投稿接口 | `403` |

## 测试结果

- API 测试组：6 passed，0 failed，0 error，20 warnings，30.45 秒。
- 完整后端回归：17 passed，0 failed，0 error，59 warnings，67.22 秒。
- 受控回归：1 failed，原因是临时移除输入校验后接口接受 `auditStatus=0` 并返回 `200`；恢复后再次通过。
